Document 3: Low-Level Software Engineering (SWE) & MCP 2025-11-25 Wire Specification
Technical judges in the Alexa+ track explicitly verify that your server speaks MCP Specification 2025-11-25 (or later) over Streamable HTTP, rather than the deprecated 2024-11-05 two-endpoint HTTP+SSE transport.
3.1 Strict MCP 2025-11-25 Streamable HTTP Compliance Rules
Your services/omnibeat-mcp-server/src/server.py MUST implement these 6 wire invariants:
1. Single Unified Endpoint (/mcp): All client-to-server JSON-RPC requests, notifications, and responses flow through one path (/mcp).
2. Origin Validation Security Gate: Per the 2025-11-25 spec, validate the Origin header on every incoming request to prevent DNS rebinding; return HTTP 403 Forbidden if an untrusted origin is detected.
3. Handshake & Session Header (Mcp-Session-Id):
   * On POST /mcp with method: "initialize", return "protocolVersion": "2025-11-25" and mint a cryptographically random Mcp-Session-Id response header.
   * Every subsequent request from the orchestrator includes MCP-Protocol-Version: 2025-11-25 and Mcp-Session-Id: <uuid>.
4. Dual Content-Type Negotiation (application/json vs. text/event-stream):
   * All client POST /mcp requests carry Accept: application/json, text/event-stream.
   * Sub-Engine 3 (ZeroYapFastPath) responds immediately with HTTP 200 OK and Content-Type: application/json (completing in under 60ms).
   * Sub-Engine 1 (PolyglotPhoneticJudo) responds with Content-Type: text/event-stream, pushing real-time SSE notifications/progress events (Stage 1: Stripping Hinglish wrapper... Stage 2: Phonetic Skeleton LLPPLGL... Stage 3: Matched canonical track) before closing with the final JSON-RPC result.
5. Multi-Round-Trip Disambiguation (InputRequiredResult / elicitation/create):
   * When Sub-Engine 2 (StudioPureGuard) finds 3 famous tracks with the exact same name (e.g., "Raja Ji" or "Tere Bina"), it returns an InputRequiredResult containing the 3-second chorus preview URLs and waits for the user's follow-up POST ("Second one!") carrying inputResponses.
6. Outage Resumability via Last-Event-ID:
   * Every SSE event emitted by our server includes a monotonic id: <session>_<seq>. When you toggle "Simulate ISP Glitch" in the demo, the client reconnects with GET /mcp and Last-Event-ID, replaying missed state notifications with zero data loss!
