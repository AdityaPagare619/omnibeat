## The `OmniBeat-MCP` Master Blueprint (Adaptive Phase-Wise Playbook)

Instead of rigid step-by-step code instructions that change the moment you swap a library, run your team through these **6 Adaptive Phases**. You only move to the next phase when the phase's **"Exit Proof"** works on screen.

1. **Lock the Storyboard & Devpost Shell First:** Hours 0 to 4 — Do not write backend code until the 3-minute script exists.
Devpost's top multi-time winners follow one golden rule: **write your Devpost project story and 3-minute video script before writing a single line of code**. This prevents you from building features that never appear in the demo.

* **What You Lock In:**
* **The 4-Scene Demo Arc:**
1. *Scene 1 (Sub-Area 1A):* Ask for a Bhojpuri/regional track with a heavy accent -> watch mangled English text morph into the real track via Phonetic + Web Search Judo.
2. *Scene 2 (Sub-Area 1B):* Ask for a song title shared by 4 remixes -> MCP triggers `input_required` and fans out 3 vinyl cards playing a stitched 3-second chorus hook of each.
3. *Scene 3 (Sub-Area 1C):* Friends laugh and banter (ignored by Banter Shield), then you sharply interrupt Alexa's long artist bio mid-sentence -> speech bubble slices in half and switches to `Brief` mode.
4. *Scene 4 (Sub-Area 1D):* Flip the **"Kill Wi-Fi / ISP Outage"** switch -> zero dead air as the player seamlessly crossfades into the `IndexedDB` local vibe cache.


* **The Architecture Contract:** Define the 4 MCP tool names (`resolve_phonetic_track`, `sample_collision_hooks`, `abort_active_yap`, `sync_offline_vibe_cache`) so frontend and backend builders can work in parallel without blocking each other.


* **Phase Exit Proof:** A drafted Devpost draft page and a 1-page JSON mock of what the MCP server will stream to the UI.


2. **Stand Up the MCP 2025-11-25 Skeleton & Wire Inspector:** Hours 4 to 12 — Prove protocol compliance before adding smart wrappers.
Judges check **Tech Implementation** first: does this actually run on MCP spec `2025-11-25+` over Streamable HTTP, or is it a fake REST API?

* **What You Build:**
* Create a single `/mcp` endpoint (Node.js/TypeScript or Python FastMCP) that negotiates protocol version `2025-11-25`, issues an `Mcp-Session-Id` header, and supports `text/event-stream` Server-Sent Events.
* Build the **Simulated Alexa+ Split-Canvas UI** shell: Left panel for the tactile Alexa+ Orb & Live Transcript; Right panel for the **OmniBeat Studio Deck**; Bottom bar for the **Live MCP Wire Inspector** (displays green badges like `MCP 2025-11-25 · POST /mcp · 42ms` on every tool call).


* **Why It stays Flexible:** At this stage, the 4 MCP tools can return dummy hardcoded songs. You are verifying the *pipe* between voice input, the LLM agent brain (e.g., Claude on Bedrock or fast API), the MCP server, and the browser UI.
* **Phase Exit Proof:** Clicking a test button in the web app triggers a real MCP tool call and renders a live JSON-RPC chip on screen.


3. **Plug In the Phonetic Judo & Chorus Disambiguator Pipelines:** Hours 12 to 28 — Sub-Areas 1A & 1B (Core Music Intelligence).
Now replace the dummy tool responses inside your MCP server with the smart engineer wrappers. If one external API gives you rate-limit trouble, swap it out without touching your UI.

* **Sub-Area 1A Pipeline (`resolve_phonetic_track`):**
* Pass the raw speech transcript through a phonetic normalizer (Double Metaphone + Hinglish/Devanagari transliteration table).
* **The Judo Move:** Query YouTube Data API / Web Search first with `"{phonetic_query} song {user_region}"` to harvest the true canonical track name, then match that clean title against Deezer/iTunes/Spotify metadata.


* **Sub-Area 1B Pipeline (`sample_collision_hooks`):**
* When multiple tracks match the canonical title with high popularity scores, return an MCP elicitation/disambiguation payload containing three 30-second MP3 preview URLs (from the free Deezer or iTunes Search API—no OAuth headaches!) with timestamps set to the high-energy chorus hook (`t=12s` to `t=15s`).


* **Phase Exit Proof:** Saying *"Play Lolly Pop La Gelu"* or an ambiguous song title visibly animates the phonetic correction pipeline and plays the 3-second audio hooks in the browser.


4. **Wire the Edge Reflexes: Cut-The-Yap & Offline Failover:** Hours 28 to 44 — Sub-Areas 1C & 1D (Client + MCP Stream Coordination).
This phase turns your project from a "cool music search tool" into an **unbeatable daily-friction killer**.

* **Sub-Area 1C (`Cut-The-Yap` & Banter Shield):**
* Drop `@ricky0123/vad-web` (or WebAudio RMS energy + pitch variance analyzer) into the frontend simulator.
* **Rule 1 (Room Banter):** Low-volume overlapping chatter + laughter spikes toggle a subtle *"Room Banter Detected — Wake Word Locked"* pill so Alexa doesn't interrupt your hangout.
* **Rule 2 (Mid-Sentence Barge-In):** Sharp single-speaker voice energy while Alexa TTS is active fires `POST /mcp` (`abort_active_yap`), halts browser audio immediately, slices the visible transcript at the exact interrupted word, and re-prompts the agent with `[USER_BARGE_IN: Respond in 5 words max]`.


* **Sub-Area 1D (`Offline Vibe Continuity`):**
* On session start, the MCP tool `sync_offline_vibe_cache` streams 5 lightweight audio preview buffers into browser `IndexedDB`.
* Wire a prominent **"Simulate ISP / Wi-Fi Drop"** toggle in the UI header. Flipping it cuts cloud calls, flips the status badge to **"Edge Continuity Mode (IndexedDB)"**, and keeps music + local voice pause/skip commands running flawlessly.


* **Phase Exit Proof:** You can interrupt Alexa mid-word and cut the internet toggle during playback without a single second of silence.


5. **Harvest the Rulebook Multipliers (Friction Log + Open Source):** Hours 44 to 54 — The 10% Judging Bonus & Mini-Challenge Eligibility.
While tired teams waste hours tweaking CSS padding, your team spends 6 focused hours collecting the easiest points in the rulebook.

* **1. Write the 10% Bonus Friction Log (`docs/FRICTION_LOG.md`):**

* **2. Spin Out the Open-Source Micro-Package:**
* Publish your 150-line phonetic regional song matcher into a clean, separate public GitHub repo with a README and 10 unit tests so your submission qualifies for the **Open Source Mini-Challenge** alongside the main Alexa+ track.


* **Phase Exit Proof:** Both links and the Friction Log table are pasted directly into your Devpost draft.


6. **Shoot the 3-Minute Demo Video & Lock Submission:** Hours 54 to 66 — Leave a 6-hour buffer before the deadline.
Devpost veterans emphasize never waiting until the final hour to export and upload your video.

* **The Winning Video Formula (180 Seconds Total):**
